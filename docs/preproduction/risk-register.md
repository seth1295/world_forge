# Pre-production Risk Register

**Status:** Initial, evidence-based prioritization for Gate A/B.  
**Owner:** WorldForge Main Lead.  
**Last reviewed:** 2026-10-30.  
**Performance efficiency:** Out of scope for pre-production QA and exit decisions.

Priority orders investigation by how early the risk can invalidate the required generator-to-Godot proof; it is not a severity grade or a performance target. Ratings stay provisional until the relevant experiment supplies evidence.

| Priority | Risk / unresolved assumption | Current evidence | Mitigation / proof needed | State |
|---|---|---|---|---|
| R1 | An inherited server can be separated from BeamNG and made to produce usable WorldForge terrain. | The generator is a BeamNG.Earth-derived application; `run_server.bat` says to start BeamNG.drive, and its current server code is still coupled to BeamNG-specific session/output concepts. Actual independence and reusable algorithms are not yet traced end to end. | Identify a minimal source-derived elevation path; run it without BeamNG; replace rather than alias engine-specific transport/output; prove with tests and exact process commands. | Gate A specialist audit in progress. |
| R2 | Real prototype elevation is available, traceable, reproducible and semantically correct for the chosen region. | Both official 3DEP `n40w077` and `n40w106` 1/3 arc-second tiles are acquired locally and SHA-256 checked. Rasterio independently verified their GeoTIFF dimensions, EPSG:4269/NAD83, Float32 type, no-data and requested crop values; sidecars identify NAVD88 metres and provide no tile-specific accuracy limit. Exact source/sidecar/product-record hashes and URLs are in `vertical-slice.md`. | Use these immutable files in an independent producer; preserve provenance through generated outputs; derive spatial tolerances from the actual source uncertainty and independent references. Do not use inherited Mapterhorn/AWS/Copernicus terrain as the approved pilot source. | Source acquisition verified; generator output and datum conversion remain open. |
| R3 | Elevation values can be placed in the chosen geographic/local coordinate frame without confusing orthometric and ellipsoidal height. | `server/geodesy.py:80–88` passes the supplied elevation as `h` to `geodetic_to_enu`; `native/earthfast/src/lib.rs:789–810` treats `h` as ellipsoidal height in the WGS84 geocentric conversion. For the approved 3DEP pilot, USGS identifies CONUS heights as NAVD88 orthometric, so reusing this path unchanged would mix height datums. The tile metadata declares EPSG:4269/NAD83 but does not give a realization/epoch. NGS says GEOID18 is for NAD83(2011) epoch 2010.0 ellipsoid heights, so applying it to an unspecified NAD83 tile is not yet justified ([NGS GEOID18 technical details](https://www.ngs.noaa.gov/GEOID/GEOID18/geoid18_tech_details.shtml), [NGS datums and frames](https://nweb.ngs.noaa.gov/datums/)). | Keep source CRS/datum and height distinct; use a source-tied local frame for the first demonstrator or identify a compatible horizontal/vertical operation before ECEF placement. Compare with independent geodetic references and document scenario-specific error limits. | Confirmed reuse hazard; source-frame strategy and global ECEF operation remain Gate B decisions. |
| R4 | The checked-out Godot engine can load and display producer output on the actual Windows workstation. | Parent `integration/` has no project. Godot is 4.8.0 beta source with no `bin/` executable. Godot source includes GDExtension, custom resource-loader and mesh APIs; no engine change is yet justified. MSVC 14.44 and Windows SDK 10.0.26100 are present, but SCons is absent. | Select a small WorldForge-native tile contract; install/use a reviewed, pinned build tool if permitted; build the pinned engine; implement a GDScript or GDExtension consumer using existing scene/resource APIs; capture and independently reproduce actual running output. | Engine API reconnaissance complete; source build not run because SCons is missing. |
| R5 | Geographic transforms retain ground-scale stability across wide coordinates, latitudes, longitude wrap and vertical datums. | Main Lead selected a bounded regional frame for WF-VS-01: source NAD83/GRS80 EPSG:4269 projected through anchor-centered AEQD, with relative NAVD88 height `H−H0`. The frames have separate anchors and are not mutually composable or geocentric. No projection-distortion bound, independent transform result or global WGS84/ECEF strategy is yet validated. Godot offers single/double `real_t`, but a double build alone would not prove renderer/physics accuracy. | Record exact WKT/operation and versions; compare forward/inverse outputs to independent references; measure radial and non-radial distortion over both crops; quantify the regional vertical-chart interpretation; separately test a global frame at high latitudes, antimeridian, poles and large coordinates. Derive tolerances from source uncertainty and scenario. | Local-frame decision adopted; quantitative and global validation not tested. |
| R6 | Async tile demand, stale-result rejection, unload, origin changes and collision readiness can be made correct using existing Godot lifecycle facilities. | No WorldForge tile manager or collision representation exists in the parent. Godot resource loading can use worker threads; active scene-tree mutation must be coordinated on the main thread. ResourceLoader does not expose cancellation. | Specify ownership, request generation IDs and unload semantics; test valid/invalid loads, cancellation or stale discard, repeated load/unload, error recovery, collision readiness and shutdown on an actual runtime. | Not tested. |
| R7 | The technology and selected source data can be reused without importing incompatible third-party code, assets or terms. | Generator root license is MIT; that does not clear bundled fonts, images, geospatial datasets or service terms. The Godot fork tracks upstream source. Root `CREDITS.md`, `SOURCES.md` and component inventories identify multiple non-USGS inputs; no global production data rights decision is established. | Audit retained source, bundled assets and every prototype source separately; preserve notices; use the adopted USGS policy for the DEM slice; record production-only rights as gates. | Initial review in progress. |
| R8 | Functional streaming and WorldForge game-system foundations can be specified without gameplay or a performance gate. | Mission scope prohibits gameplay; parent has no entity or persistence contract. | Implement only geographic positioning, streamed-object identity/lifecycle and minimal state interfaces needed for production planning; validate against reload and origin changes. Defer gameplay and efficiency work. | Not yet scoped after Gate C. |
| R9 | Independent review and integration evidence can be obtained safely and against exact revisions. | QA Lead and two engineering departments are separate agents. The GitHub MCP identity reads the owned repositories; no PR exists and write/review permission is unverified. `git submodule status` currently fails in Git for Windows with a signal-pipe error, although parent gitlinks match child heads. The managed command sandbox restricts writes and networking but still allows reads outside a test directory. QA accepts the seven no-write and six fake-fetcher tests after source inspection when the latter use a task-specific workspace temp adapter; broad discovery and uninspected build hooks remain unsuitable. | Use exact-SHA review assignments from the fixed local template and record reviewer evidence. Continue using `git ls-tree`/child `rev-parse` if submodule-status remains unavailable. Inspect each test's imports, side effects and output path; restrict it to approved fixtures and an explicit command. | QA setup active; no verdict or approval. |

## Evidence discipline

This is an open-risk list, not a completion declaration. Update each row with a current commit, test command/result, artifact or source citation as evidence becomes available. Keep observed facts, engineering hypotheses and not-run checks distinct. Resolve critical assumptions with functional and geographic tests; do not add performance thresholds.
