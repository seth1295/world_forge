## Experiment

Build a small, standalone pipeline that takes official USGS 3DEP bare-earth GeoTIFF data, produces a versioned engine-neutral WorldForge terrain-grid artifact, and loads that exact artifact in the pinned WorldForge Godot source build for ground-level inspection.

Use two geographically separated regions. The Baltimore, Maryland, window is centered near **39.2900° N, 76.6100° W**, with crop `[-76.6200, 39.2800, -76.6000, 39.3000]`. The Front Range near Golden, Colorado, is centered near **39.7550° N, 105.2200° W**, with crop `[-105.2400, 39.7450, -105.2000, 39.7650]`. Both XML sidecars disclaim an accuracy warranty and neither gives a tile-specific accuracy value. USGS's collection-level accuracy figure is context only, not a per-tile bound. Use only the fallback conditions in `prototype-data-policy.md`.

The selected regional projection definitions are:

- Baltimore: `+proj=aeqd +lat_0=39.28995370377841 +lon_0=-76.60995370372139 +datum=NAD83 +x_0=0 +y_0=0 +units=m +no_defs +type=crs`
- Golden: `+proj=aeqd +lat_0=39.754953704278655 +lon_0=-105.21995370310027 +datum=NAD83 +x_0=0 +y_0=0 +units=m +no_defs +type=crs`

The ellipsoidal AEQD projection preserves ellipsoidal geodesic distance radially from its center; it does not preserve all pairwise distances. Measure radial and transverse/non-radial scale over the crop using boundary corners and representative cross-crop pairs, and compare radial distances with an independent GRS80 geodesic implementation. Record sampled errors separately from the derived bound. These are horizontal chart distances: do not call them slope distances or claim elevation-corrected ground distance. The source realization and ellipsoid heights are unspecified, so the demonstration does not claim exact physical terrain distances.

The contract must store the exact generated CRS WKT as well as the source CRS, source anchor pixel row/column, transformation library/version and row/column mapping. Godot maps projected East→X, relative NAVD88 height→Y, and projected North→−Z. All adjacent tiles, LODs and collision for one region share the same AEQD origin and projection; an origin shift subtracts a local offset without changing that frame. Independently recentering an adjacent tile requires a verified frame conversion. The consumer must reject or explicitly transform coordinates from the other region. These custom frames differ by region and cannot be used as globally compatible coordinates.

Keep the independent producer in the generator repository, with an entrypoint that works without BeamNG.drive, BeamNG assets, or BeamNG runtime hooks. The parent integration repository owns the schema/contract and the Godot technical viewer. The existing Godot fork is built at its pinned revision; no engine-core modification is planned.

For the first consumer, use Godot's existing GDScript file APIs and scene/resource facilities (`FileAccess`, `ArrayMesh`, and an appropriate collision resource) to parse the versioned artifact and construct a technical terrain view. This directly exercises the selected engine build and keeps the first interface engine-neutral. The Godot department's source review found a GDExtension `ResourceFormatLoader` feasible if runtime resource loading requires it. Revisit a native extension, module, or core modification only after a reproducible acceptance failure proves the existing integration/runtime APIs insufficient.

For this regional demonstrator, retain the source geographic reference `EPSG:4269` (NAD83/GRS80) and project each region into a custom NAD83/GRS80 Azimuthal Equidistant frame centered on its exact source-grid anchor. Baltimore's origin is (`−76.60995370372139°`, `39.28995370377841°`) and Golden's is (`−105.21995370310027°`, `39.754953704278655°`). The local axes are East and North in metres; each region has a distinct frame identity and its coordinates must never be combined directly with the other region's local coordinates. The projection is radial-distance preserving from the anchor; measure non-radial distortion over each crop as part of acceptance.

The vertical sample remains NAVD88 orthometric metres. Set `H0` to the recorded height of the exact anchor sample and local mesh up to `H − H0`. This is a **regional projected elevation frame**, not ENU, ellipsoidal height, WGS84 or ECEF. `H0` is a source-derived camera baseline, not surveyed ground truth. The source origin, horizontal projection and all local coordinates must remain traceable. This representation proves local geographic positioning; it does not establish geocentric placement.

The acquired metadata does not name a NAD83 realization or epoch. Do not apply GEOID18 or silently turn NAVD88 values into ellipsoidal height: NGS restricts GEOID18 to NAD83(2011) epoch 2010.0 ellipsoid heights. WF-VS-01 may prove regionally positioned terrain in its declared source frame, while global WGS84/ECEF placement remains unproven until the source realization and a compatible horizontal/vertical operation are established. Test the global spatial model separately with fully specified independent reference fixtures. This regional slice alone cannot close WF-EXIT-05.

Gate B specified the manifest, binary framing, data types, coordinate/datum fields and lifecycle contract in the parent terrain schema and `terrain-grid-contract.md`. The parent Godot consumer now rejects malformed, incompatible or stale data before geometry allocation; preserve source metadata and do not introduce an undocumented ad-hoc format.

## Why this slice

It tests the mission's critical dependency chain in the fewest components while exercising the main risks identified so far: legitimate real-data acquisition, independent production, an engine-neutral exchange, datum semantics, high-precision geographic placement, the actual Windows Godot build, renderer/collision construction and repeatable runtime capture. An imported static mesh or synthetic terrain would skip the producer, source semantics or consumer and would not satisfy the experiment.

## Acceptance criteria for WF-VS-01

1. **Source provenance:** Each of the two regions uses an actual acquired USGS 3DEP raster. Preserve exact official source URL/product ID, acquisition date, source metadata/sidecar, tile footprint, original grid/CRS/vertical reference/units/no-data values, bytes and SHA-256. Record any crop, conversion or resampling with inputs and tool versions.
2. **Independent production:** A documented generator command reads those real files without BeamNG and writes the versioned WorldForge artifact. Re-running from the same immutable source and parameters gives a compatible, verifiable output; it must not silently substitute inherited Mapterhorn, AWS, Copernicus or synthetic data.
3. **Coordinate and elevation correctness:** Preserve input `EPSG:4269`, GIS raster axis order (X = longitude, Y = latitude), NAD83/GRS80, NAVD88 orthometric height and metres. Build a per-region Azimuthal Equidistant projection from the exact anchor and document its parameters, axes, units, extent and measured non-radial distortion. Define the anchor `H0` from an exact source grid sample and use only `H − H0` for regional mesh up; never pass it or `H` into an ellipsoidal-height/ECEF API. Check forward/inverse horizontal coordinates against an independent implementation and explicit NAD83 reference values. Any requested global ECEF placement must fail explicitly or report unavailable until a compatible source realization and vertical transformation are established. Main Lead sets scenario-specific numeric limits after source uncertainty and independent references are available; do not invent a global tolerance.
4. **Real engine consumer:** Build the exact pinned Godot revision on Windows, load producer output at both actual coordinates, construct/render the generated terrain, and inspect it from a ground-level technical camera. Demonstrate the rendered geometry is derived from the recorded source tile and generator output, not a hardcoded sample.
5. **Capture reproduction:** Record parent/engine/generator/contract SHAs, executable build/version/hash, dataset/source hash, coordinates, camera pose, renderer/configuration, exact build/launch/capture commands, artifact path and observed result. QA independently reproduces or inspects the capture from the actual running build.
6. **Functional streaming:** Exercise async request/loading, readiness before terrain/collision use where applicable, adjacent tile/LOD transitions, stale completion after unload or relocation, repeated load/unload/revisit, input or generation failure, recovery and shutdown. Record ownership and resource cleanup. These are correctness tests, not efficiency tests.
7. **Geographic coverage:** The production logic is not location-hardcoded. Test at least two separated real-data regions and independent reference coordinates in their declared source frames. Also test the separate global coordinate model against fully specified fixtures at large magnitudes, differing latitudes, longitude wrap/antimeridian and polar or other edge cases as applicable; real terrain data need not cover those synthetic-reference cases.
8. **Rights:** Keep USGS source metadata and attribution with the local evidence bundle. Audit code and any other data sources separately. No uncleared imagery, map data or third-party assets may be substituted to improve the screenshot.

## Not proven by this experiment alone

This slice does not establish full-Earth dataset coverage, global feature completeness, production-ready terrain fidelity, production throughput or hardware efficiency, complete collision support for every structure, final gameplay or release rights for non-USGS content. The handoff must keep these items in the risk register and production roadmap.
